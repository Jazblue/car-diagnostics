Car Diagnosis — Security Audit Report

Date: 25 Aug 2026  •  Scope: desktop app + web app
Summary
Overall risk: Low
The apps are mostly local-first, use parameterized DB access, and do not send sensitive data to remote services.
1. Injection
Status: OK
  • SQLite queries use parameterized statements with ? placeholders.
  • No raw string concatenation for SQL.
  • No shell command execution from user input.
2. Input Handling / Validation
Status: OK — hardened
  • Added _safe_text() truncation for all persisted fields.
  • Web inputs use maxLength constraints.
  • Dates validated before MOT/Tax save.
3. Serial / OBD2 Adapter
Status: OK — hardened
  • Connection failures handled with try/except.
  • Serial port closed safely on failure.
  • No remote execution path.
4. Data Storage
Status: Acceptable for offline use
  • Local SQLite DB is unencrypted.
  • Local JSON config is unencrypted.
  • Risk is low because the app is designed for offline single-user use.
5. Web App Exposure
Status: OK
  • Pure client-side React app.
  • No backend API, no auth tokens, no third-party tracking.
  • Data stays in browser localStorage.
6. Dependencies
Status: OK
  • Desktop: only pyserial added; standard library otherwise.
  • Web: standard Next.js/React stack.
  • No obvious dependency risk from app logic.
7. Recommendations
  • Keep the app offline-only unless the user explicitly wants cloud sync.
  • Avoid adding authentication unless needed.
  • If shared PCs are used, consider OS-level folder permissions for the DB/config files.
